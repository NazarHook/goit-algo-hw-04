## Завдання 1. Сортування файлів за розширенням

```bash
python task_1.py <source> [destination]
```

Якщо `destination` не вказано, використовується `dist`. Функція `copy_files` рекурсивно обходить `source` і копіює кожен файл у `destination/<розширення>/`. Файли без розширення потрапляють у `no_extension`. Помилки доступу виводяться в stderr, обхід триває.

## Завдання 2. Сніжинка Коха

```bash
python task_2.py
```

Програма питає рівень рекурсії і малює сніжинку через `turtle`. Рівень 0 дає трикутник, кожен наступний рівень замінює кожну сторону на 4 сторони втричі коротші.

## Завдання 3. Порівняння сортувань

```bash
python task_3.py
```

Порівнюються сортування вставками, сортування злиттям і Timsort (`sorted`). Час міряється через `timeit` (середнє за 1-3 запуски, секунди). Сортування вставками має складність O(n²), тому для n > 5000 його пропущено. Результати кожного алгоритму перевіряються порівнянням із `sorted`.

### Висновки

1. **Вставками: O(n²).** На випадкових даних при зростанні n у 2 рази час зростає приблизно у 4 рази (1000: 0.0053, 2000: 0.0226, 5000: 0.144). На зворотних даних це ще гірше. Вже при n = 5000 він у 40 разів повільніший за злиття.
2. **Злиттям: O(n log n).** При зростанні n у 10 разів (10000 до 100000) час зростає у 12.7 раза, що відповідає n log n. Час майже не залежить від порядку даних.
3. **Timsort: O(n log n) у гіршому випадку.** На випадкових даних він у 10-15 разів швидший за наше злиття. Частково це заслуга реалізації на C, але не лише її.
4. **Відсортовані та зворотні дані.** Timsort знаходить у масиві вже впорядковані послідовності (run) і зворотні розвертає за один прохід. Тому для 100000 елементів він працює за 0.0002-0.0004 с, тобто за O(n), а злиття витрачає 0.06 с. Сортування вставками теж швидке на відсортованих даних (O(n)), але на зворотних дає O(n²).
5. **Чому комбінація вдала.** Timsort ділить масив на короткі run-и, впорядковує їх вставками (на малих масивах вставки швидкі, бо мають малі константи), а потім зливає злиттям. Так він бере сильні сторони обох алгоритмів: швидкість вставок на малих і майже впорядкованих даних і гарантовані O(n log n) злиття на великих.

Власні реалізації не мають переваг перед вбудованими `sorted` і `list.sort`. Вони повільніші, а на реальних даних, які часто частково впорядковані, різниця ще більша. Тому в більшості випадків використовують вбудоване сортування.
